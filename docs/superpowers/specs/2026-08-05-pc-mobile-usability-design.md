# PC mobile usability

Two problems with the in-game PC on phones, following up on the mobile support
pass (`2026-08-05-mobile-support-design.md`): the terminal can't be typed into
without a physical keyboard, and the zoomed-in monitor is small and mushy.

## Problems

1. **No way to type.** Free-text entry (`pc.mode === ASK` with `pc.prompt ===
   PROMPT`) is handled by a single `window.addEventListener("keydown", ...)`
   in `game.js` (~1486-1512) gated on `pc.captured && pc.on`. It never focuses
   a DOM element, so there is nothing for a touchscreen to attach an on-screen
   keyboard to. `terminalPromptHit`/`terminalLinkAt` already let you click
   `[link]`s and the bare prompt (comment at 1460: "keeps the whole game
   playable without a keyboard"), but any command that needs actual typed
   text is unreachable on a phone. This includes the `sudo` password prompt,
   which the prior mobile-support spec explicitly left desktop-only for lack
   of a way to type; a working keyboard bridge makes it reachable on mobile
   too as a side effect, superseding that carve-out.

2. **Monitor is small.** `resize()` (game.js:1870) sets `camera.fov =
   fovFor(camera.aspect)`, which is a single global FOV used by every zone.
   `fovFor` (1861) locks the *horizontal* FOV by widening the vertical FOV as
   aspect narrows — correct for general navigation (that's the mobile-support
   spec's fix), but the `pc-screen` marker's camera transform in
   `scripts/scene.json` (`markers["pc-screen"]`) is a fixed position/rotation
   that was framed assuming the desktop FOV (`data.camera.fov`, 60°). On a
   portrait phone `fovFor` returns close to `MAX_FOV` (125°), so from that
   same fixed camera position the monitor subtends a much smaller angle than
   on desktop.

3. **Monitor is pixelated.** The terminal text is drawn onto a canvas texture
   sized by the `cmd` `Label3D` node (`makeLabel` in game.js:343, fed by
   `data.labels` in scene.json): `font_size: 31`, `width: 1000`. That
   resolution was fine at desktop framing; zoomed in tighter (see #2's fix)
   and at mobile device pixel ratios, the same texel density reads as mushy.
   `scripts/scene.json` is generated by `tools/build.py` from
   `.godot/temp.dog/tscn/scene.tscn` (`Label3D` fields `font_size`, `width`,
   `pixel_size` → JSON `font`, `w`, `px`), so it must not be hand-edited
   directly or the next scene export will silently discard the fix.

Out of scope: touching the `tv-screen` zoom, which has the same FOV-locking
exposure in principle but wasn't reported as a problem, and the desktop PC
framing, which is unaffected by any of this (mobile only, per direction).

## Design

### 1. Hidden-input keyboard bridge

Add one hidden `<input>` to `index.html` (e.g. `#pcInput`), not part of the
3D scene, styled to take no visual space (off-screen or zero-size, not
`display:none` — needs to stay focusable) with `autocomplete="off"
autocorrect="off" autocapitalize="off" spellcheck="false"
enterkeyhint="send"`.

`game.js` tracks a `pcInputMirror` string that always equals what the hidden
input's `.value` was last set to.

- **Opening the keyboard:** in the existing tap path (`tryTerminalClick`,
  reached from the canvas `pointerdown` handler), when `isMobile &&
  pc.captured && pc.mode === ASK`, set `pcInput.value = pcInputMirror =
  pc.buffer` and call `pcInput.focus()`. This runs inside the same gesture
  that already exists, so no new gesture-handling is needed for the keyboard
  to be allowed to appear.
- **Typing:** on the hidden input's `input` event, compare `pcInput.value`
  against `pcInputMirror` to get the inserted/deleted span (a plain
  common-prefix/common-suffix diff — same idea as diffing two strings, no
  library needed). Apply that as a sequence of the same primitive operations
  `pc.buffer` already supports (append char if `pc.label.fits(...)` allows
  it, or truncate), then set `pcInputMirror = pcInput.value` and repaint.
  Diffing the resulting value (rather than trusting individual `keydown`
  events) is what makes this robust against Android autocorrect/predictive
  text rewriting whole words at once.
- **Submitting:** the hidden input's own `keydown` still reliably fires for
  `Enter` on both iOS and Android soft keyboards, so `Enter` there calls the
  existing `submitLine()` path directly (same logic as desktop's `Enter`
  handling), then resets `pcInput.value = pcInputMirror = ""`.
- **Closing the keyboard:** `pcInput.blur()` whenever `zoneBack()` leaves
  `pc-screen`, so the keyboard doesn't linger after backing out of the PC.
- Desktop is untouched: the existing `window` `keydown` handler keeps working
  exactly as today (it doesn't depend on any element being focused), and
  `pcInput.focus()` is only ever called when `isMobile`.

### 2. Compensating PC-screen zoom (mobile only)

`gotoZone` (game.js ~653-674) currently passes the `pc-screen` marker's
`position`/`rotation` straight to `setZone` unchanged. The camera looks down
its own local -Z axis (standard three.js/`PerspectiveCamera` convention), so
"dolly in" means: take the marker's forward vector (its `rotation` quaternion
applied to `(0, 0, -1)`), and move the marker's `position` further along that
same vector before handing it to `setZone` — i.e. push the camera forward,
toward whatever it's already aimed at, without changing its rotation. Only
when `isMobile && zone === "pc-screen"`, translate by:

```
distance_moved_in = markerDistanceGuess * (1 - tan(baseFov/2) / tan(currentFov/2))
```

using `baseFov = data.camera.fov` and `currentFov = fovFor(camera.aspect)` —
the same ratio `fovFor` used to widen the view, applied in reverse. Desktop
(`fovFor` returns `data.camera.fov`, ratio 1, zero translation) and every
other zone are unaffected since the compensation only ever triggers for this
one marker under `isMobile`. `markerDistanceGuess` is a small fixed constant
(the approximate camera-to-monitor distance already implied by the
`pc-screen` marker, eyeballed from `scripts/scene.json`) rather than a
computed raycast, since this only needs to look right, not be physically
exact.

### 3. Higher-resolution terminal canvas (moderate bump)

Edit the `cmd` `Label3D` node in `.godot/temp.dog/tscn/scene.tscn`:
multiply `font_size` and `width` by ~1.5x, and divide `pixel_size` by the
same 1.5x so the label's on-screen world-space size is unchanged — only the
texel density goes up. Keep `NearestFilter`/no mipmaps in `makeLabel`
unchanged, per your call to keep some retro chunkiness rather than go fully
crisp. Regenerate `scripts/scene.json` with `python tools/build.py` rather
than hand-editing the JSON.

## Testing

No test framework in this repo (static site); verification is manual:

- Desktop: PC framing, zoom, and typing via physical keyboard are pixel/byte
  identical to before (diff `scripts/game.js`/`scripts/scene.json` behavior
  at `isMobile === false` should be a no-op).
- Mobile emulation (Chrome device toolbar or a real phone): tapping the
  terminal while it's asking for input brings up the on-screen keyboard;
  typing, backspacing, and autocorrect-triggered word replacement all end up
  correctly reflected in `pc.buffer`; `Enter` submits; leaving the PC zone
  dismisses the keyboard. The monitor at `pc-screen` fills a similar fraction
  of the screen as it does on desktop, and its text is legibly sharper than
  before while still reading as pixel art rather than antialiased.
